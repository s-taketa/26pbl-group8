# セキュリティ設計書 — コエミマ

| 項目 | 内容 |
|---|---|
| バージョン | 1.0 |
| 更新日 | 2026-07-09 |
| 位置づけ | セキュリティ要件・対策方針、および実運用に向けた対応項目を定義する |

本システムはカメラ映像・生活ログという機微な個人情報を扱うため、実運用の前に本書の「要対応」項目の解消を前提とする。

---

## 1. 実装済み（対策できている点）
| 項目 | 内容 |
|---|---|
| パスワード保護 | Werkzeug でハッシュ保存（平文保存なし） |
| SQLインジェクション | SQLAlchemy ORM のパラメータ化で概ね防止 |
| XSS | ダッシュボード描画時に HTML エスケープ（`esc()`） |
| 画像アクセス制御 | `/images/<file>` はログインセッション必須 |
| 多要素認証 | ログイン時のメール2段階認証（SMTP設定時） |
| 認証コード有効期限 | 5分で失効 |

---

## 2. 要対応（既知の課題とリスク）

### 2.1 重大
| ID | 課題 | リスク | 対策方針 |
|---|---|---|---|
| S-01 | パスワード再設定がコード検証と未連動 | 第三者が任意アカウントのPWを変更可能 | コード検証成功をセッション/トークンで担保し、`/api/reset-password` はそれがある宛先のみ許可 |
| S-02 | `/api/*` の多くが認可なし | カメラのログ・設定が誰でも取得/変更可能 | 全 `/api/*` にログイン必須化。`/api/recognition`・`/video` はエッジ用トークンで保護 |
| S-03 | オープン登録 ＋ 全ユーザー共通ログ | 到達可能な第三者が登録し全ログ閲覧可能 | 登録の招待制/承認制、またはユーザー（世帯）ごとのログ分離 |
| S-04 | エッジ `/video` が無認証 | 同一LANの第三者がライブ映像を閲覧 | トークン/basic認証、またはサーバー経由配信に限定 |

### 2.2 高
| ID | 課題 | 対策方針 |
|---|---|---|
| S-05 | HTTP（平文通信） | リバースプロキシ（Nginx等）でHTTPS化 |
| S-06 | 秘密情報の管理 | `.env` をGit管理外に、`.env.example` はダミー値、鍵は定期ローテーション（Geminiキー漏洩→自動無効化の実績あり） |
| S-07 | `FLASK_SECRET_KEY` 既定値 | ランダム値を必須化（未設定だとセッション偽造可） |

### 2.3 中
| ID | 課題 | 対策方針 |
|---|---|---|
| S-08 | レート制限なし | ログイン/登録/コード送信に試行回数制限（総当たり・メール爆撃対策） |
| S-09 | CSRF対策なし | 状態変更APIにCSRFトークン、SameSite Cookie |
| S-10 | 画像/ログの無期限・平文保存 | 保存期間・削除ポリシー、必要に応じ暗号化 |
| S-11 | 本番でFlask開発サーバー | gunicorn 等の本番WSGIへ |

---

## 3. 対策優先度（推奨ロードマップ）
1. **S-01 / S-02 / S-03 / S-04**（重大：第三者に映像・ログが渡る経路を塞ぐ）
2. **S-07 / S-06**（セッション鍵・秘密情報）
3. **S-05**（HTTPS化）
4. **S-08 / S-09 / S-11**（堅牢化・本番化）

---

## 4. 個人情報の取り扱い方針（案）
- 取得：カメラ画像、発話内容、AI回答、通知履歴
- 目的：見守り（状況把握・緊急通知）に限定
- 保管：サーバー内（画像はファイル、テキストはMySQL）
- 共有：登録された家族アカウントのみ（将来は世帯単位で限定）
- 削除：保存期間経過後に自動削除（今後実装）
