# セキュリティ設計書 — コエミマ

| 項目 | 内容 |
|---|---|
| バージョン | 2.1 |
| 更新日 | 2026-07-09 |
| 位置づけ | セキュリティ要件・対策方針、および実運用に向けた対応項目を定義する |

本システムはカメラ映像・生活ログという機微な個人情報を扱うため、実運用の前に本書の「要対応」項目の解消を前提とする。

---

## 1. 実装済み（対策できている点）
| 項目 | 内容 |
|---|---|
| パスワード保護 | Werkzeug でハッシュ保存（平文保存なし） |
| セッション鍵 | `FLASK_SECRET_KEY`（未設定時はプロセスごとにランダム生成）で署名。固定既定値を用いない |
| セッションCookie強化 | `HttpOnly`・`SameSite=Lax` を付与。JSからの読み取りとクロスサイトPOST送信を抑止し、CSRFの主要経路を遮断（HTTPS環境では `FORCE_HTTPS=1` で `Secure` 属性も付与可） |
| API認可 | ダッシュボード・設定系API（`/api/dashboard`, `/api/settings`, `/api/sync-settings`, `/images/<file>`）はログイン必須 |
| 新規登録の本人確認 | メール宛の登録は確認コード検証後に初めてアカウントを作成（他人のメールアドレスでの登録を防止） |
| パスワード再設定の本人確認 | 認証コード検証に成功した宛先のみ再設定を許可（セッションで担保。宛先不一致は 403） |
| 多要素認証 | ログイン時のメール2段階認証（SMTP設定時） |
| 認証コード有効期限 | 5分で失効 |
| レート制限 | ログイン・登録・確認コード関連APIに試行回数制限（同一IPから5分間に5〜10回まで） |
| エッジ通信の保護（任意設定） | `EDGE_API_TOKEN` 設定時、`/api/recognition`・`/api/edge-config` およびエッジの `/video`・`/command` を共有トークンで保護 |
| 秘密情報の管理 | `.env` はGit管理対象外、`.env.example` はダミー値のみ |
| SQLインジェクション | SQLAlchemy ORM のパラメータ化で概ね防止 |
| XSS | ダッシュボード描画時に HTML エスケープ（`esc()`） |

## 2. 要対応（既知の課題とリスク）

### 2.1 重大
| ID | 課題 | リスク | 対策方針 |
|---|---|---|---|
| S-01 | 全ユーザーで認識ログが共通 | 登録できたユーザーは全ログ（カメラ映像・会話履歴）を閲覧可能 | ユーザー（世帯）ごとのログ分離、または登録の招待制/承認制 |
| S-02 | `EDGE_API_TOKEN` は任意設定（未設定時は無認証） | 設定を怠るとエッジ通信・映像配信が無防備なまま | 導入時に必ず `EDGE_API_TOKEN` を設定する運用を徹底し、将来的には必須化を検討 |

### 2.2 高
| ID | 課題 | 対策方針 |
|---|---|---|
| S-03 | HTTP（平文通信） | リバースプロキシ（Nginx等）でHTTPS化。あわせて `FORCE_HTTPS=1` を設定 |

### 2.3 中
| ID | 課題 | 対策方針 |
|---|---|---|
| S-04 | レート制限がプロセス内メモリのみ | 複数ワーカー/複数インスタンス構成では効果が限定的。Redis等の外部ストアへ置き換え |
| S-05 | CSRFトークン本体は未実装 | `SameSite=Lax` で大半は緩和済みだが、状態変更APIへの明示的なCSRFトークン付与を検討 |
| S-06 | 画像/ログの無期限・平文保存 | 保存期間・削除ポリシー、必要に応じ暗号化 |
| S-07 | 本番でFlask開発サーバー | gunicorn 等の本番WSGIへ（バックグラウンドスレッド起動処理の見直しが必要） |

---

## 3. 対策優先度（推奨ロードマップ）
1. **S-01**（重大：登録できれば全ログが見える状態の解消）
2. **S-02**（`EDGE_API_TOKEN` の運用徹底）
3. **S-03**（HTTPS化）
4. **S-04 / S-05 / S-06 / S-07**（堅牢化・本番化）

---

## 4. 個人情報の取り扱い方針（案）
- 取得：カメラ画像、発話内容、AI回答、通知履歴
- 目的：見守り（状況把握・緊急通知）に限定
- 保管：サーバー内（画像はファイル、テキストはMySQL）
- 共有：登録された家族アカウントのみ（将来は世帯単位で限定）
- 削除：保存期間経過後に自動削除（今後実装）
