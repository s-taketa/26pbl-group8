## 1. システム概要

### 1.1 背景と目的
視覚に不安のある方や離れて暮らす高齢者が、**声だけ**で周囲の状況を確認し、家族が遠隔から見守れる環境を提供する。難しい機器操作を必要とせず、危険を検知した際は家族へ自動で通知する。

### 1.2 ターゲットユーザー
- **メインユーザー**：視覚に不安のある方／見守り対象の高齢者
- **サブユーザー（補助者）**：離れて暮らす家族・介護補助者

### 1.3 全体構成
Raspberry Pi 5（エッジ）と Ubuntu サーバーを組み合わせたハイブリッド構成。システムを構成する技術要素は次の2つ。

- **エッジ（Raspberry Pi 5）**：撮影・音声入出力・ウェイクワード検知・物理ボタンなど「体」の役割に専念（軽量）。
- **サーバー（Ubuntu / Docker）**：AI解析・音声合成・DB・通知・**Webフロントエンド（管理ダッシュボード）**など「脳」の役割を集約（重い処理）。

家族・介護補助者（1.2のサブユーザー）は、サーバーが提供する **Webフロントエンド（ダッシュボード）** をブラウザから操作し、**LINE通知**で緊急連絡を受け取る形でシステムを利用する。家族自身は本システムの構成要素（エッジ／サーバー）ではなく、フロントエンドとLINEを介した利用者（アクター）である。

AI解析（Gemini）と音声合成（VOICEVOX）はサーバーに集約し、Pi5 の CPU 負荷軽減と応答速度向上を図る。音声認識（Vosk）はエッジ側でローカルに完結する。

## 2. システム構成

### 2.1 ハードウェア構成
「使用技術.md」を参照。要点：Raspberry Pi 5＋カメラモジュール（NoIR）＋USBマイク＋USBスピーカー＋物理プッシュボタン（GPIO18）。サーバーは Ubuntu 24.04 LTS の常時起動機。

### 2.2 ソフトウェア構成
「使用技術.md」を参照。要点：
- エッジ：Python 3.11 / Vosk（STT）/ OpenCV・Picamera2（撮影）/ Flask（命令待受・映像配信）/ gpiozero（ボタン）
- サーバー：Python 3.11 / Flask（API・画面）/ Google Gemini API（AI）/ VOICEVOX（TTS）/ MySQL 8.0（DB）/ Docker Compose

---

## 3. 機能設計

### 3.1 サーバー（Ubuntu）
- **3.1.1 管理ダッシュボード提供**：補助者がブラウザでリアルタイム映像・認識ログ・通知履歴を確認。PCは統合レイアウト、スマホはレスポンシブ対応。
- **3.1.2 認証・アカウント管理**：ID/パスワード認証（ハッシュ保存）、新規登録、パスワード再設定（メール認証コード）、ログイン時のメール2段階認証（SMTP設定時）。
- **3.1.3 AI状況解析**：エッジから受け取った画像＋発話テキストを Gemini 2.5 Flash に渡し、状況の言語化と緊急度判定を行う。
- **3.1.4 音声合成（TTS）**：AIの回答を VOICEVOX で音声化。**文単位でストリーミング返却**し、最初の一文から即再生できるようにする。
- **3.1.5 中央データ管理（MySQL）**：認識ログ（画像パス・質問・回答・緊急フラグ）、通知履歴、システム設定を永続化。
- **3.1.6 通知**：緊急検知時に家族の LINE へ自動通知。設定により通常時の会話ログ送信・定期通知も可能。
- **3.1.7 エッジ連携**：ハートビート応答、ウェイクワード設定の配信（`/api/edge-config`）。

### 3.2 エッジ（Raspberry Pi 5）
- **3.2.1 オフライン常時ウェイクワード監視**：Vosk により「チャピー」「起動して」等を完全ローカルで常時監視。表記ゆれ吸収（カタカナ→ひらがな正規化＋あいまい一致）と発話途中(partial)検知で精度を確保。
- **3.2.2 物理ボタン起動**：GPIO18 の物理ボタンでも即時起動可能（音声が拾えない場面の確実な起動手段）。
- **3.2.3 コマンド聞き取り（STT）**：ウェイクワード後、Vosk で利用者の発話をテキスト化。RMSベースの無音終端判定で早期に打ち切る。
- **3.2.4 カメラ制御・前処理**：Picamera2＋OpenCV で撮影。NoIRカメラの青み補正（R-B入れ替え）を実施し JPEG 化。
- **3.2.5 サーバー通信**：撮影画像＋発話テキストを `/api/recognition` へ送信し、返却された音声（WAV）を順次再生。
- **3.2.6 リアルタイム映像配信**：`/video`（MJPEG）でダッシュボードにライブ映像を提供。

### 3.3 外部サービス連携
- **3.3.1 Google Gemini API（2.5 Flash）**：画像＋テキストのマルチモーダル解析。回答・緊急フラグ・カテゴリを構造化JSONで取得。
- **3.3.2 LINE Messaging API**：家族へのプッシュ通知。
- **3.3.3 Gmail SMTP**：認証コード（パスワード再設定・ログイン2段階）のメール送信。

音声認識（STT）はエッジの Vosk で行う。エッジ⇔サーバー間は同一LAN内での通信を前提とする。

## 6. 処理フロー（全体概要）

利用者（視覚に不安のある方）とエッジ・サーバーの処理に加え、家族・補助者（フロントエンド／LINE利用側）がどこで関わるかを示す全体概要。詳細な処理順序（API呼び出し・外部サービスとの通信）は「詳細設計書.md 3.1」を参照。

```mermaid
flowchart TD
    subgraph U["利用者（視覚に不安のある方）"]
        U1[合言葉 or 物理ボタンで起動]
        U2[質問を話す]
        U3[AIの回答を音声で聞く]
    end

    subgraph SYS["コエミマ本体（エッジ＋サーバー）"]
        S1[ウェイクワードを検知し撮影]
        S2[AIが画像と質問を解析]
        S3{緊急と判定?}
        S4[回答を音声合成して返す]
        S5[認識ログをDBに記録]
    end

    subgraph F["家族・補助者（フロントエンド／LINE側）"]
        F1[ダッシュボードで映像・履歴を確認]
        F2[LINEで緊急通知を受け取る]
        F3[通知設定・ウェイクワードを変更]
    end

    U1 --> S1 --> U2 --> S2 --> S4 --> U3
    S2 --> S5 --> F1
    S2 --> S3
    S3 -- はい --> F2
    S3 -- いいえ --> S5
    F3 -.->|設定反映| SYS
```

## 7. 非機能要件

### 7.1 性能・応答速度
| 指標 | 目標値 | 実現方式 |
|---|---|---|
| ウェイクワード検知の反応時間 | 発話終了から **1秒以内** | 音声チャンク単位（約0.25秒／チャンク）で逐次判定 |
| コマンド聞き取りの無音終端判定 | 発話終了から **0.8秒** で聞き取り終了 | RMSベースの無音検知（`silence_limit=0.8s`） |
| コマンド聞き取りの最大待機時間 | **5秒** | タイムアウト後は聞き取れた範囲で確定（`timeout=5s`） |
| AI応答（最初の一文の再生開始まで） | **3秒以内**（目標） | 回答を文単位で合成し、できた文から順次ストリーミング再生 |
| ダッシュボードの自動更新間隔 | **5秒** | ポーリングでログ・状況を再取得 |
| エッジ⇔サーバーの死活監視間隔 | **30秒** | ハートビート送信・ウェイクワード設定同期 |
| 認証コードの有効期限 | **300秒（5分）** | メール認証コード（ログイン2段階・パスワード再設定） |
| 定期通知の間隔 | 既定 **60分**（1〜1440分で設定可） | `PERIODIC_NOTIFY_MINUTES` |

### 7.2 精度
| 指標 | 目標値 | 実現方式 |
|---|---|---|
| ウェイクワードのあいまい一致しきい値 | 類似度 **0.82以上** | `difflib.SequenceMatcher` によるゆらぎ吸収（カタカナ→ひらがな正規化＋長音/促音除去） |
| ウェイクワード誤検知抑制 | 無音/過大音のチャンクを除外 | RMSノイズゲート（下限50・上限30000） |

### 7.3 可用性
| 指標 | 目標値 | 実現方式 |
|---|---|---|
| 稼働時間 | 家庭内常時利用のため **24時間連続稼働** を想定 | ハートビート監視で死活確認。冗長構成は無し（単一サーバー・単一エッジ） |
| 依存サービス障害時の継続動作 | DB／AI／音声合成／LINE／メールのいずれかが利用不可でもサーバー起動・他機能は継続 | 各モジュールをフォールバック付きで初期化（未接続時はログのみでスキップ） |

### 7.4 セキュリティ
「開発/セキュリティ設計書.md」を参照。パスワードはハッシュ保存、認証必須API、パスワード再設定は認証コード検証済みの宛先のみ許可。

### 7.5 保守性
クラス分割（エッジ／サーバー）、Docker Compose によるコンテナ管理、設定値は環境変数（`.env`）で外部化。
